# 企业商业管理平台（EBMP）产品说明书

> 版本：v1.0.0 ｜ 发布日期：2026-11-03  
> 交付范围：OA 协同办公 · CRM 客户关系 · SRM 供应商协同 · 进销存仓储 · 合同中心 · 经营驾驶舱 · 审批引擎 · 移动端 H5  
> 运行形态：Web 门户（PC） + Android APK（移动） + REST API（集成）

---

## 一、产品定位

### 1.1 一句话定义

**一套统一底座的企业商业管理平台**，把 OA、CRM、SRM、进销存四大业务整合到同一套用户、权限、审批、主数据体系里，跨模块自动流转数据，消灭信息孤岛。

### 1.2 解决的核心问题

| 现状 | EBMP 如何解决 |
|---|---|
| 多套系统多套账号多套菜单 | 统一门户，一个登录入口，一个待办中心 |
| 客户/供应商/物料各系统各自维护，名称对不上 | 一份主数据，全平台共享，业务单据只存 ID |
| 采购需求 → 采购订单 → 入库 → 供应商评价靠 Excel 传话 | 一条 SRM 全链路，数据自动流转 |
| 线索 → 商机 → 赢单 → 销售订单 → 出库要多次录入 | 一条 CRM→进销存 全链路，赢单直接生成订单 |
| 请假/采购/销售/合同各走各的审批流，审批人记不住 | 统一审批引擎，部门负责人自动一级审批，金额≥5 万加总经理终审 |
| 库存变动多处改，对不上账 | 所有出入库只走 `StockService`，留完整流水 |
| 老板不知道今天生意怎么样 | 经营驾驶舱一页看销售/采购/库存/客户/待办全貌 |

### 1.3 设计原则

1. **整合而非拼接**：不是把四套系统用胶水粘在一起，而是在统一底座上重新实现每个能力。
2. **主数据先行**：客户/供应商/物料/仓库只维护一份，业务单据只引用 ID。
3. **状态机驱动**：DRAFT → PENDING → APPROVED → 执行，统一枚举统一渲染。
4. **业务与审批解耦**：业务模块只管提交和回调，审批引擎管编排，新增业务只需实现 `ApprovalHandler`。
5. **零依赖可演示**：开发环境用内置 H2 文件库，一条命令启动；生产切 MySQL 只改 profile。

### 3.7 审批引擎

| 能力 | 说明 |
|---|---|

## 四、跨模块业务链路

### 4.1 销售全链路（CRM → 进销存）

```
线索登记
  └─ 转化 → 客户 + 商机
        └─ 商机推进（六阶段漏斗）
              └─ 赢单（填物料明细）→ 销售订单草稿
                    └─ 提交审批（部门负责人 → 金额 ≥ 5 万加总经理）
                          └─ 审批通过 → 出库发货（选仓库）
                                └─ 扣减库存 + 生成流水 + 订单 DONE
```

### 4.2 采购全链路（SRM → 库存）

```
采购需求（部门提报，多行明细）
  └─ 提交审批 → 通过
        └─ 生成采购订单（选供应商）
              └─ 提交审批 → 通过
                    └─ 收货入库（选仓库，按明细回写 receivedQty）
                          └─ 增加库存 + 生成台账
                                └─ 供应商评价（质量/交期/服务/价格）
                                      └─ 供应商绩效汇总
```

### 4.3 合同链路（合同中心 → 审批 → CRM/SRM）

```
创建合同（CUSTOMER / SUPPLIER）
  └─ 提交审批（合同强制加总经理节点）
        ├─ 客户合同 → CRM 审批
        └─ 供应商合同 → SRM 审批
              └─ 通过 → ACTIVE 并记录签订时间
```

### 4.4 审批链路（全模块统一）

```
业务单据提交 → ApprovalService 编排节点 → 审批中心/待办可见
    → 逐级通过 → 业务回调 onApproved → 单据状态推进 → 可执行下一步
    → 任一级驳回 → 业务回调 onRejected → 单据 REJECTED（可修改后重提）
```

## 五、单据状态机

| 单据 | 状态流转 |
|---|---|
| 采购需求 | DRAFT → PENDING → APPROVED → CONVERTED / REJECTED |
| 采购订单 | DRAFT → PENDING → APPROVED → PARTIALLY_RECEIVED → RECEIVED / REJECTED |
| 销售订单 | DRAFT → PENDING → APPROVED → OUTBOUND → DONE / CANCELLED / REJECTED |
| 合同 | DRAFT → PENDING → ACTIVE / REJECTED / EXPIRED |
| 请假单 | DRAFT → PENDING → APPROVED / REJECTED |
| 审批单 | PENDING → APPROVED / REJECTED（节点级：PENDING → APPROVED / REJECTED） |
| 库存预警 | 低于安全库存自动生成，补货后自动消失 |

### 7.2 三种部署方式

#### 方式 A：快速体验（Windows 原生 · 零依赖 · 内置 H2）

```
双击 deploy\scripts\start-backend-h2.bat     → 后端 http://127.0.0.1:8080
双击 deploy\scripts\start-frontend.bat       → 前端 http://127.0.0.1
浏览器访问 http://127.0.0.1
停止：双击 deploy\scripts\stop-all.bat
```

#### 方式 B：Linux 原生 + MySQL 生产库

```bash
cd deploy

# 1. 建库（首次）
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS ebmp DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2. 启动后端（MySQL 版）
export MYSQL_URL='jdbc:mysql://127.0.0.1:3306/ebmp?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
export MYSQL_USER=root
export MYSQL_PASSWORD='ChangeMe@123'
bash scripts/start-backend-mysql.sh

# 3. 启动前端静态托管
bash scripts/start-frontend.sh 80

# 4. （可选）用 Nginx 反代 /api → 后端，/ → 静态资源
sudo cp frontend/nginx/ebmp-server.conf /etc/nginx/conf.d/ebmp.conf
sudo nginx -t && sudo systemctl reload nginx

# 停止
bash scripts/stop-all.sh
```

#### 方式 C：Docker Compose（一键生产部署）

```bash
cd deploy/docker
docker compose up -d
# 访问 http://服务器IP
# 日志：docker compose logs -f backend
```

## 十一、FAQ

**Q1：H2 和 MySQL 怎么切？**  
启动脚本或 docker-compose 的 `SPRING_PROFILES_ACTIVE` 改为 `mysql`，并配置 `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` 即可；首次启动 Hibernate 自动建表。

**Q2：前端 80 端口被占用？**  
Windows 下先 `SET PORT=8081` 再启动；Linux 下 `bash scripts/start-frontend.sh 8081`。

**Q3：移动端连不上后端？**  
① 手机浏览器访问 `http://后端IP:8080/api/health` 看能不能通；② 手机和后端在同一网段；③ 启动页服务器地址改为后端实际 IP。

**Q4：如何新增业务模块接入审批？**  
实现 `ApprovalHandler` 接口（`bizType()`、`onApproved()`、`onRejected()`），Spring 自动发现，无需改审批引擎。

**Q5：如何新增权限码/菜单？**  
后端在角色权限里加新权限码，前端 `AppLayout.vue` 的菜单配置加 `perm: 'new:perm'`，即可按角色过滤。

**Q6：数据会丢吗？**  
H2 文件库自动落到 `backend/data/ebmp.mv.db`；MySQL 生产库 + 定时 `mysqldump`，建议每日备份。
