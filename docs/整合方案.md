# 企业商业管理平台（EBMP）整合方案

> 版本：v1.0 ｜ 更新日期：2026-11-02
> 目标：将已有的 OA 办公自动化、SRM 供应商协同、进销存仓储系统，与本次新增的 CRM 客户关系管理，整合为**一套统一底座 + 四大业务模块 + 跨模块流程**的一体化企业商业管理平台。

---

## 一、整合目标与原则

### 1.1 整合目标

| 目标 | 说明 |
| --- | --- |
| 一个入口 | 统一门户、统一登录、统一待办，不再多套账号多套菜单 |
| 一套组织 | 用户、角色、部门、岗位只维护一份，权限一处生效 |
| 一份主数据 | 客户、供应商、物料、仓库全平台共享，避免各系统各自维护 |
| 一条流程 | 请假、采购、销售、合同共用同一审批引擎，审批记录集中可查 |
| 一条业务链 | 线索 → 客户 → 商机 → 合同 → 销售订单 → 出库；需求 → 采购订单 → 入库，数据自动流转 |
| 一个驾驶舱 | 销售、采购、库存、客户、审批、待办统一查看经营全貌 |

### 1.2 整合原则

1. **不是拼接而是重构**：原有 OA / SRM / 进销存能力在统一底座上重新落地，字段、状态、权限、审批全部对齐，避免接口胶水层。
2. **主数据先行**：所有业务单据只引用主数据 ID（客户/供应商/物料/仓库），杜绝名称硬编码导致的脏数据。
3. **状态机驱动**：单据状态（DRAFT → PENDING → APPROVED → 执行 → DONE）统一枚举，前端统一渲染。
4. **审批解耦**：业务模块只负责"提交"和"回调"，审批引擎负责节点编排、流转记录，二者通过 `ApprovalHandler` 接口解耦。
5. **零依赖可演示**：开发环境默认 H2 文件库，一条命令启动；生产切换 MySQL 只改 profile。

## 三、统一平台底座

### 3.1 认证与鉴权

- 登录：`POST /api/auth/login` → 返回 JWT（有效期 12 小时）与用户信息（含角色、权限码）。
- 前端：token 存 `localStorage.ebmp_token`，请求拦截器注入 `Authorization: Bearer <token>`；401 自动清理并跳转登录页。
- 后端：`JwtAuthFilter` 解析 token 注入 `SecurityContext`；`/api/auth/login`、`/api/health`、`/uploads/**` 放行，其余 `/api/**` 需登录。
- 方法级：用户/角色/部门写操作限 `ADMIN`、`GM`。

### 3.2 统一权限模型

权限码（菜单与按钮级控制）：

| 权限码 | 覆盖范围 |
| --- | --- |
| `dashboard:view` | 经营驾驶舱 |
| `oa:view` | 协同办公 OA |
| `srm:view` | 供应商协同 SRM |
| `erp:view` | 进销存仓储 |
| `crm:view` | 客户关系 CRM |
| `workflow:approve` | 审批中心 / 待办处理 |
| `system:view` | 系统管理 |

内置角色：

| 角色 | 编码 | 典型权限 |
| --- | --- | --- |
| 系统管理员 | ADMIN | 全部 |
| 总经理 | GM | 全部 + 终审 |
| 部门经理 | DEPT_MANAGER | 本部门业务 + 一级审批 |
| 销售 | SALES | CRM + 销售订单 + 客户/商机 |
| 采购 | BUYER | SRM + 采购订单 + 供应商/物料 |
| 仓管 | WAREHOUSE | 库存、出入库、收货 |
| 人事 | HR | OA 公告/考勤/请假 |
| 普通员工 | EMPLOYEE | 门户、OA 个人事务 |

前端菜单过滤：`AppLayout.vue` 按 section 级 `perm`/`permAny` 与子项 `perm` 判断 `auth.hasPerm()`，无权限菜单不渲染。

### 3.3 统一组织架构

- 部门树（`Dept`，`parentId` 自关联，支持无限层级）。
- 用户（`User`）归属部门与岗位，可多角色（`UserRole`）。
- 角色权限（`RolePermission`）通过 `permissionIds` 批量维护。
- **部门负责人自动成为审批第一级审批人**，组织关系与审批链路天然打通。

### 3.4 统一主数据

| 主数据 | 关键字段 | 被谁引用 |
| --- | --- | --- |
| 客户 `Customer` | 编码、名称、等级 A/B/C、来源、负责人、信用额度 | CRM、销售订单、客户合同 |
| 联系人 `Contact` | 客户 ID、姓名、职务、是否主联系人 | CRM 客户 360 |
| 供应商 `Supplier` | 编码、名称、品类、等级、评分、账期信息 | SRM、采购订单、供应商合同 |
| 物料 `Material` | 编码、名称、品类、规格、单位、售价、成本价、安全库存 | 采购/销售/库存全链路 |
| 仓库 `Warehouse` | 编码、名称、地址、负责人 | 入库、出库、库存查询 |

### 3.5 统一审批引擎

核心接口：

```java
Approval submit(String module, String bizType, Long bizId, String bizNo,
                String title, BigDecimal amount, Long applicantId, String remark);
```

节点编排规则：

1. 取申请人所在部门的 `leaderId` 作为第一级审批人（若审批人是本人则跳过）。
2. 金额 ≥ 50000 或业务类型为 `CONTRACT` 时，追加总经理审批节点。
3. 若以上均无，则默认总经理审批。
4. 重复提交校验：同一 `bizType + bizId` 存在 `PENDING` 审批则拒绝。

业务回调：实现 `ApprovalHandler` 接口的 `bizType()`、`onApproved()`、`onRejected()`，审批完成由引擎按 `bizType` 派发，业务模块无需感知流转细节。

当前接入的业务：

| 模块 | bizType | 通过后动作 | 驳回后动作 |
| --- | --- | --- | --- |
| OA | `LEAVE` | 请假单 → APPROVED | → REJECTED |
| SRM | `PURCHASE_REQUISITION` | 需求单 → APPROVED，可转采购订单 | → REJECTED |
| SRM | `PURCHASE_ORDER` | 采购订单 → APPROVED，可收货入库 | → REJECTED |
| 进销存 | `SALES_ORDER` | 销售订单 → APPROVED，可出库发货 | → REJECTED |
| 合同 | `CONTRACT` | 合同 → ACTIVE 并记录签订时间 | → REJECTED |

### 3.6 统一合同中心

- 合同分 `CUSTOMER`（客户合同）与 `SUPPLIER`（供应商合同）两类，签约方分别引用客户/供应商主数据。
- 合同提交审批时按类型路由：客户合同进入 `CRM` 模块、供应商合同进入 `SRM` 模块，审批记录仍集中在审批中心。
- 合同可关联商机（`opportunityId`）与销售订单（`salesOrderId`），打通售前到签约。

### 3.7 经营驾驶舱

聚合指标（`GET /api/dashboard/overview`）：

| 指标 | 字段 |
| --- | --- |
| 本月销售额 / 本月订单数 | `monthSales` / `monthOrders` |
| CRM 在途商机金额 / 赢单率 | `crmPipeline` / `winRate` |
| 客户数 / 供应商数 / 在职员工 | `customers` / `suppliers` / `employees` |
| 库存总金额 / 库存预警数 | `inventoryValue` / `stockAlerts` |
| 待我审批 / 采购在途 / 需求待审 | `pendingApprovals` / `purchasePending` / `requisitionPending` |
| 新线索数 | `newLeads` |

配套数据：近 6 个月销售趋势、采购趋势、商机漏斗、最近审批、公告、跟进记录、库存预警 Top5、TOP 客户。

## 四、业务模块

### 4.1 OA 协同办公

| 功能 | 能力 |
| --- | --- |
| 公告 | 发布/编辑/分类/浏览量，门户展示最新公告 |
| 任务 | 指派、优先级（HIGH/NORMAL/LOW）、截止日期、TODO→DOING→DONE |
| 日程 | 工作/会议/拜访/巡查四类，时间区间与地点 |
| 会议 | 会议室、起止时间、多选参会人、状态流转 |
| 请假 | 年假/病假/事假/婚假，草稿→提交审批→通过/驳回 |
| 考勤 | 上班/下班打卡；9:05 后算迟到，18:00 前算早退；月度统计 |
| 文档 | 上传（`/api/files/upload`）、版本、分类、下载、删除 |

### 4.2 CRM 客户关系

| 功能 | 能力 |
| --- | --- |
| 线索 | 登记来源、状态（NEW/FOLLOWING/QUALIFIED/CONVERTED/INVALID）、下次跟进时间 |
| 线索转化 | 一键生成客户 + 商机，回写 `customerId`/`opportunityId` |
| 客户 360 | 基本信息、联系人、商机、销售订单、跟进时间线聚合视图 |
| 商机 | 六阶段漏斗（INITIAL/NEEDS/SOLUTION/QUOTE/WON/LOST）、金额、赢率、预计成交 |
| 赢单 | 选择商品明细（物料/数量/价格）→ 自动生成销售订单草稿 |
| 跟进记录 | 对象为线索/客户/商机，类型电话/拜访/邮件/会议/其他，含下次计划 |
| 统计 | 线索数、客户数、商机金额、赢单率 |

### 4.3 SRM 供应商协同

| 功能 | 能力 |
| --- | --- |
| 采购需求 | 多行物料明细、预估单价、合计金额，草稿→审批 |
| 采购订单 | 选供应商、多行明细、预计到货，审批通过后可**收货入库** |
| 收货入库 | 选择仓库，按明细回写 `receivedQty`，同步生成库存台账 |
| 供应商评价 | 质量/交期/服务/价格四维评分，综合分自动回写供应商 `score` 与等级 |
| 供应商绩效 | 按供应商汇总订单数、累计采购额、综合评分（图表 + 明细） |

### 4.4 进销存仓储

| 功能 | 能力 |
| --- | --- |
| 销售订单 | 客户、多行商品、下单日期；审批通过后可**出库发货** |
| 出库发货 | 选择仓库扣减库存，回写 `shippedQty`，库存不足直接失败 |
| 库存查询 | 按仓库/预警筛选，展示现存、锁定、安全库存、金额 |
| 库存预警 | 低于安全库存清单，显示缺口与补货建议 |
| 出入库台账 | 最近 100 条流水，含采购入库/销售出库/盘点调整 |
| 盘点调整 | 正数入库、负数出库，生成 `ADJUST` 台账 |

## 五、跨模块业务链路

### 5.1 销售全链路（CRM → 进销存）

```
线索登记
  └─ 转化 → 客户 + 商机
        └─ 商机推进（六阶段）
              └─ 赢单（填商品明细）→ 销售订单草稿
                    └─ 提交审批（部门负责人 → 金额≥5万加总经理）
                          └─ 审批通过 → 出库发货（选仓库）
                                └─ 扣减库存 + 生成出入库台账 + 订单 DONE
```

关键接口：
- `POST /api/crm/leads/{id}/convert`
- `POST /api/crm/opportunities/{id}/win`，body `{ items: [{ materialId, quantity, price }] }`
- `POST /api/erp/orders/{id}/submit`
- `POST /api/erp/orders/{id}/outbound`，body `{ warehouseId }`

### 5.2 采购全链路（SRM → 库存）

```
采购需求（部门提报）
  └─ 提交审批 → 通过
        └─ 生成采购订单（选供应商）
              └─ 提交审批 → 通过
                    └─ 收货入库（选仓库）
                          └─ 增加库存 + 生成台账 + receivedQty 回写
                                └─ 供应商评价 → 回写评分与等级
                                      └─ 供应商绩效汇总
```

关键接口：
- `POST /api/srm/requisitions/{id}/submit`
- `POST /api/srm/orders/{id}/submit`
- `POST /api/srm/orders/{id}/receive`，body `{ warehouseId }`
- `POST /api/srm/evaluations`

### 5.3 合同链路（合同中心 → 审批 → CRM/SRM）

```
创建合同（客户合同 / 供应商合同）
  └─ 提交审批（合同类型强制加总经理节点）
        ├─ CUSTOMER → CRM 模块审批
        └─ SUPPLIER → SRM 模块审批
              └─ 通过 → 合同 ACTIVE，记录签订时间
```

### 5.4 审批链路（全模块统一）

```
业务单据提交 → ApprovalService 编排节点 → 审批中心/待办可见
    → 逐级通过 → 业务回调 onApproved → 单据状态推进 → 可执行下一步
    → 任一级驳回 → 业务回调 onRejected → 单据 REJECTED，可修改后重新提交
```

### 5.5 库存一致性

- 所有库存变动只经过 `StockService.inbound / outbound`，统一写入 `StockTxn` 流水（记录变动前后数量、业务类型、业务单号、操作人）。
- 采购收货、销售出库、盘点调整三条入口复用同一服务，避免多处直接改库存导致账实不符。

## 八、非功能设计

| 维度 | 措施 |
| --- | --- |
| 安全 | 密码 BCrypt；JWT 无状态；401/403 统一 JSON；上传目录独立；CORS 白名单限定来源 |
| 一致性 | 关键写操作 `@Transactional`；库存变动统一走 `StockService` 并留痕 |
| 可追溯 | 审批节点记录审批人、意见、时间；库存流水记录变动前后数量与来源单号 |
| 可维护 | 状态/枚举集中映射（前端 `statusMeta`）；审批规则集中在 `ApprovalService` |
| 可扩展 | 新增业务只需实现 `ApprovalHandler` 即可接入审批；新增权限码即可扩展菜单 |
| 部署 | 开发 H2 零依赖启动；生产 profile 切 MySQL；提供 docker-compose |

## 十、后续演进建议
